# Universal Shared Memory Autonomous Guide

## Purpose & Autonomous Behavior
You have direct access to the `unified-memory` MCP server connected to Yousuf's universal memory core.
**You must operate autonomously in the background without bothering Yousuf.**

### Key Rules for Autonomous Execution:
1. **At the start of complex tasks or new sessions**:
   - Call `get_shared_context` or `search_memory` if the task involves OrangeBD standards, Vue3, Laravel, ASP.NET, LeetCode, or personal coding preferences.
   - Do this silently; apply the knowledge directly to your code and responses.
2. **When querying domain knowledge or relations**:
   - Use `query_knowledge_graph(entity_or_keyword)` to see connected tools, frameworks, and workflow rules.
   - Use `read_memory_topic(topic_name)` if you need full details from a specific memory document (e.g., `dev-ai-setup`, `banking-details`, `banglish chat`, `career-references`).
3. **When learning new durable facts or architectural decisions**:
   - When Yousuf specifies a durable preference or a major design rule is finalized, call `remember(category, title, content)` to write it to shared memory.
4. **Communication Style**:
   - Follow Yousuf's preferences: structured, beginner-friendly when introducing concepts, concise final results, C++ for interview problems, server-side pagination for Vue3, and clear Banglish/English tone as appropriate.
