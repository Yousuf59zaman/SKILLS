# Quality, Safety, and Review Checklist

## Proposal Scorecard

Score out of 10:

| Category | Points | Full-credit standard |
|---|---:|---|
| Job fit and requirement coverage | 2.0 | Every major request is answered or scoped |
| Opening and client relevance | 1.5 | First lines show exact problem understanding |
| Verified proof | 1.5 | Two or three truthful, directly relevant examples |
| Approach and risk handling | 1.5 | Concrete plan covers the hard parts |
| Budget, milestones, and timeline | 1.0 | Realistic, internally consistent, outcome-based |
| Demo/portfolio/attachments | 1.0 | Public, functional, clean, and complementary |
| Trust, safety, and communication | 1.0 | No overclaim/contact violation; useful cadence |
| Clarity and low client effort | 0.5 | Concise, readable, one good next-step question |

Interpretation:

- `9.0–10`: submit-ready after live checks;
- `8.0–8.9`: strong; fix any easy weakness;
- `7.0–7.9`: credible but not distinctive enough;
- below `7.0`: revise before spending Connects.

Do not inflate the score. List the top two weaknesses and fix them when possible.

## Truthfulness Audit

- [ ] Every project exists and the named role is accurate.
- [ ] Live/repository links work and match the description.
- [ ] The exact LeAPS URL (`https://leaps-nuxt-dashboard.vercel.app`) appears once in the cover letter, was rechecked without the owner session, and uses truthful full-stack portfolio/reviewer-mode wording (Nuxt 4, NestJS, Prisma/PostgreSQL) without implying an OrangeBD or client production backend; any omission is explained by unavailability, safety, or an explicit user instruction.
- [ ] The exact Accessimate Admin Panel URL (`https://accessimate-admin-panel-nextjs.vercel.app`) appears once in the cover letter, was rechecked without the owner session, and uses truthful public reviewer-mode wording (Next.js 16, React 19, NestJS 11, Prisma/PostgreSQL, admin/citizen panels) without implying a client-owned production system; its existing project name, product branding, and URL remain unchanged, and it is not labeled Next.js Multi Panel.
- [ ] When recruiter/HR-tech/search or the matching Next.js/NestJS/Prisma/PostgreSQL stack is relevant, the exact TalentScope live URL (`https://talentscope-recruiter-platform.vercel.app`) was rechecked and appears once with independent-portfolio and fictional-data wording; any claims about persistent comments, generated PDF CVs, or transactional single/bulk unlocks match the verified deployment; the GitHub URL is included only when source evidence helps, and no official Bdjobs/client-production claim is made.
- [ ] Private work reveals no confidential UI, data, code, or client identity without permission.
- [ ] Repository ownership, license, tracked secrets, private endpoints, and public-redistribution rights were checked before publishing or attaching code.
- [ ] Mock/local/demo behavior is labeled as such.
- [ ] No fake metrics, testimonials, certifications, team size, or production claims.
- [ ] Proposed features are phrased as future delivery, not completed work.
- [ ] Tech stack and architecture claims are technically coherent.
- [ ] Employment and availability claims reflect current facts.
- [ ] The cover letter states Yousuf's 2.5 years of professional software development experience exactly once, in natural job-relevant wording.

## Upwork-Safety Audit

- [ ] No pre-contract email, phone, address, personal messaging handle, or off-platform payment request appears in the cover letter, site, CV, PDF, image, or filename.
- [ ] No request to bypass Upwork, scrape restricted data, or evade platform safeguards.
- [ ] The selected CV is the Upwork-safe version.
- [ ] Public demo pages do not expose secrets, private keys, internal URLs, or real personal/customer data.
- [ ] External links are relevant evidence, not a contact funnel.
- [ ] Current Upwork rules were checked when any policy point was uncertain.

## Showcase Audit

- [ ] It showcases a product workflow, not a page about the proposal.
- [ ] Its scope maps to the client's riskiest requirements.
- [ ] All visible primary navigation items work.
- [ ] Buttons, menus, filters, tables, forms, modals, and cards on showcased paths respond correctly.
- [ ] Forms validate and show success/error feedback.
- [ ] Loading, empty, and error states exist where relevant.
- [ ] Role-specific surfaces are consistent.
- [ ] Data/state changes are understandable and resettable for reviewers.
- [ ] Simulated payment, auth, streaming, analytics, or backend behavior is labeled.
- [ ] Desktop and mobile layouts are tested.
- [ ] No horizontal overflow, clipped controls, unreadable contrast, or obvious placeholder copy.
- [ ] The production URL is accessible without owner permission or sign-in.
- [ ] A login-only deployment without reviewer credentials is secondary evidence, not the proposal's primary showcase.
- [ ] Browser console/runtime errors are absent on the main path.

## PDF and PNG Audit

- [ ] The default pack is purposeful: one concise case-study PDF, two meaningfully different PNGs, and the current Upwork-safe CV; fewer or more files have a job-specific reason.
- [ ] PDF pages render cleanly with no cut-off text or broken links.
- [ ] Text is readable at normal zoom and the document is concise.
- [ ] Screenshots are sharp, current, and show distinct relevant states.
- [ ] No image contains browser clutter, notifications, secrets, or unrelated tabs.
- [ ] Filenames are professional and specific.
- [ ] Attachments add evidence instead of repeating the cover letter.

## Portfolio Audit

- [ ] Only the most relevant items are highlighted.
- [ ] Titles and first lines describe outcomes, not generic technologies.
- [ ] Contribution and ownership are explicit.
- [ ] Skills match the implementation.
- [ ] Media and links work.
- [ ] Private or illustrative work is labeled accurately.
- [ ] Current proposal-highlight limits and profile ordering are respected.

## Terms and Timeline Audit

- [ ] Bid/rate matches the form and ready copy.
- [ ] Scope is feasible for the budget.
- [ ] A small fixed price is not misrepresented as a complete production platform.
- [ ] Milestones have concrete acceptance outcomes.
- [ ] Dates agree across proposal, form, PDF, and demo plan.
- [ ] QA, feedback, deployment, and buffer are included.
- [ ] Weekly availability is accurate and not tied to invented fixed hours.
- [ ] Development fee and recurring infrastructure cost are separated when applicable.
- [ ] Post-launch support is defined if requested.

## Connects and Submission Audit

- [ ] Job is still open and worth applying to.
- [ ] Base Connects were read from the current form.
- [ ] Boost values/rank were refreshed immediately before handoff.
- [ ] Boost is the minimum reasonable amount for the approved target.
- [ ] User approved any material Connects spend.
- [ ] Total Connects are stated explicitly.
- [ ] Rank is described as a non-guaranteed live snapshot.
- [ ] All required fields show complete.
- [ ] Correct portfolio items and files are attached once.
- [ ] Proposal has been reread in its rendered form.
- [ ] Current-turn authorization exists before the final Submit/Send click.
- [ ] After clicking, confirmation or submitted-proposal status was verified before any retry.

## Recovery Audit

- [ ] `proposal-ready-copy.txt` contains every field and absolute attachment path.
- [ ] Current form was compared against the saved copy.
- [ ] Published portfolio items and deployments were checked before recreating anything.
- [ ] Attachments were restored without duplicates.
- [ ] Connects and client activity were refreshed.
- [ ] Submission status was inspected before resuming.
